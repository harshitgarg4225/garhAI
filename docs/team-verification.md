## The question

Every signup created a firm with exactly one admin, and no route could add a second
person (`docs/trial-readiness.md`, "Collaboration"). Presence, live cursors and
colleague comments were built, firm-scoped, and unreachable by any two humans. The
sign-up copy promised "invite the rest of the studio" and "add your CoA later in firm
settings"; neither place existed. The login page branched on error codes the server
never emits and collected a mobile number it discarded.

## TRACED

- **Acceptance is the mailbox, not the link.** `AuthService.request_otp` sends a code
  to an address with an open invite (`AuthDirectoryRepository.find_open_invite_by_email`,
  newest-first across firms); `verify_otp` accepts on a verified code when no account
  exists (`_accept_invite` → `accept_invite` + `assign_invited_seat` + `invite.accepted`).
  The token in the email resolves only to the status page and is stored as `sha256`.
- **Seat at acceptance is best-effort by design** (`garh_api/invites.py::assign_invited_seat`):
  a plan that shrank between invite and acceptance yields a seatless member the Team
  page shows, not a sign-in refused with a billing error. Not exercised by a test — the
  branch needs a plan downgrade between two HTTP calls.
- **Role changes reach a live session on the next refresh** (≤ 15 min): `AuthService.refresh`
  re-reads the principal. Removal, by contrast, is immediate (generation bump + family
  sweep), asserted in `test_removing_a_member_ends_their_live_sessions`.
- **The Practice page's title-block card writes through `PUT /firm/drawing-preferences`**,
  re-sending every other preference unchanged; only the firm-level `TitleBlockFields`
  (firm name, drawn by, checked by, notes, logo) are editable there.
