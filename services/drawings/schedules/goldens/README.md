# `services/drawings/schedules/goldens/`

Golden output for the two §7 table sheets. **Every file here was generated by the code
it guards** — nothing in this directory was hand-written or hand-adjusted, which is the
only condition under which a golden is worth anything (golden rule 10, §16).

| File | What it pins |
|---|---|
| `schedule-demo-g1.txt` | door/window schedule of the folded G+1 demo — tags, sizes, per-storey counts, totals |
| `schedule-demo-g1.json` | the same schedule as data, including `tagByOpeningId` (the map the plan projection labels openings from) |
| `schedule-demo-g1.svg` | the same table as a §13-sanitised SVG (paper mm, no script, no `foreignObject`, no external refs) |
| `schedule-blr-far-road-9-18m.txt` | the schedule derived from a **rules** `EvaluationContext` instead of a model — proves both source adapters agree |
| `area-statement-blr-far-road-9-18m.txt` | the municipal area statement: plot, coverage, per-storey built-up, carpet, FAR, setbacks, floors, height, parking |
| `area-statement-blr-far-road-9-18m.svg` | the same, as SVG |
| `setbacks-blr-far-road-9-18m.txt` | the setback table on its own (the site plan prints this next to the plot) |

## Sources

* `fixtures/rules/blr/blr.far.road.9-18m.pass.json` — a committed rule fixture: a real
  300 m² Bengaluru plot on a 9 m road where the FAR, coverage, setback, floors, height
  and parking rules all fire. Its numbers come from the **rules engine**, so these
  goldens also pin the "same numbers, one source" contract.
* `fixtures/model/golden-states.json` → case `storeys-stair-levels`, folded by the real
  `garh_model`, plus eleven `opening.add` ops defined in
  `services/drawings/tests/test_schedules.py`. Real ops, real fold, real derived rooms.

## Regenerating

```bash
python3 services/drawings/tests/test_schedules.py --regen   # rewrite
python3 services/drawings/tests/test_schedules.py           # verify (byte-diff, tolerance 0)
pytest -q services/drawings/tests/test_schedules.py         # same, in CI
```

A golden diff is a build failure, not a warning. If the change is intended, regenerate
and commit the golden **in the same change**, with a note saying which number moved and
why — a reviewer must be able to tell an intended re-tag from an accidental one.

## Why text and SVG, and not DXF

Text and SVG are pure string output: this machine can genuinely produce them, so they
are real goldens. DXF needs `ezdxf`, which is pinned but not installed here (see the
toolchain-gap row in `DECISIONS.md`), so there are no DXF goldens in this directory —
a golden nobody generated is worse than no golden.

The `.txt` form deliberately carries no coordinates. It fails when a *number*, a *tag*
or a *row order* changes — the things a contractor builds from — and not when a column
is nudged 1 mm. The `.svg` form covers the geometry.
